## 这个模式做什么

学生**自己做**。给一道题，他独立解完、交上来，我们判卷；过了进复习，没过转引导。

三个模式里只有它先要结果：guide 从零带，work 先放手，HRL 拿结果去打磨。

## 三个模式是一条闭环

```
work ──(判过)──────────> review ──> mastered
  │
  ├──(没过)──> guide ──> 做出来 ──> review
  │
  └──(过了但答得糙)──> HRL ──> review
```

work 是入口，guide 和 hrl 是两条补救路径，bankmanager 记状态，schedule 派活。

## 和别的模式怎么分

| | guide（`dsh-plugin-guide`） | work（本包） |
|---|---|---|
| 学生的起点 | 还没做出来 | 拿到题，自己做 |
| 我们做什么 | 给注意力，不给动作，不评价 | 不插手，等他交，然后判 |
| 什么算结束 | 他自己走完一遍、能说清为什么 | 判过，或者转 guide |

和 HRL 的分界在**顺序**：work 是第一次做，HRL 是回过头改。同一道题先 work 后 HRL，不冲突。

## 判卷（草案）

判两件事，分开记：

1. **结果对不对**
2. **说清楚没有**——为什么是这一步、为什么不用别的

两个都过才算过。只有结果对、理由说不出来，不判错，转 guide 补「为什么」——他做出来了，只是不知道自己怎么出来的。

判卷前得先自己解一遍，和 guide 的前置工作一样。

## 没过之后

不立刻转 guide。先给一次机会：只指出错在哪一步（不给方法），让他重交。还不行才切 guide。

理由：work 的价值在「自己先撞一次」。一次就转，work 就退化成 guide 的序章了。

## 做题时给什么、不给什么

- **给**：查资料。考的是解题，不是背书。
- **不给**：提示。他中途问「这步对不对」，最多回「先按你的想法写完，我们再一起看」。
- **不挂** guide 的提示词和 `read_note`：科目备注里写着「怎么验对不对」，那是判卷标准，不能提前给他。

## 还没定的问题

- **判卷由谁做**：模型直接判（快，但容易嘴软），还是先抽出最终答案再比、只有理由部分交给模型？
- **「说清为什么」怎么判**：追问一句让他讲，还是看交上来的步骤里有没有？
- **重交几次**：一次不过就转 guide，还是给两次？
- **答案怎么交**：打字、手写拍照（认字成本高），还是公式输入。
- **转 guide 带不带上下文**：把这次的解题过程一起带过去，还是重开一段会话。
- **会话形态**：一道题一个会话？能不能一次交几道？
- **要不要限时**：模拟考试就限时，日常练习不限。
- **显示名和预设 id**：id 预定 `work`，显示名待定（「独立做题」？「练习」？）。
