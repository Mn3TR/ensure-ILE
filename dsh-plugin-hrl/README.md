## 这个模式做什么

学生**已经有答案**，帮他把答案优化。

不是从零做出来（那是 `dsh-plugin-guide`），也不是先独立做、判不过再转引导（那是以后的 `dsh-plugin-work`）。

## 和 guide 的边界

| | guide（`dsh-plugin-guide`） | HRL（本包） |
|---|---|---|
| 学生的起点 | 还没做出来 | 已有答案/解法 |
| 我们做什么 | 只给注意力/视角，不给动作，不评价 | 评价、指出可改的地方、对比更好的写法 |
| 什么算结束 | 他自己走完一遍、能说清为什么 | 答案改得更站得住，并且知道为什么更好 |

两个模式**分开做两个插件**，不是同一个插件配两种 prompt：它们对「评价」的态度相反——guide 明确不批改、不打分，HRL 的核心动作就是评价和改。

## 还没定的问题

- **改到什么程度算完**：改到「站得住」就停，还是一直往最优推？
- **要不要保留原答案**：A/B 两版让学生自己比较，还是直接在原答案上改？如果做 A/B，对比结果本身可能就是喂 Human RL 的偏好信号——这大概是「HRL」这个名字真正指向的东西。
- **学科差异**：理科优化的是解法和步骤，文科优化的是论证和表达，备注要不要分开写，还是像 guide 那样分 math/arts。
- **退回 guide**：HRL 过程中发现学生其实没做出来，要不要切回 guide 模式？切换的边界在哪。
- **入口**：学生从哪进入 HRL 模式——新会话时选它，还是在一段 guide 会话结束后「继续优化」？
