## 这个插件做什么

把三样输入变成每天能直接用的清单：

- **输入**：课表（周循环）、讲课节奏（一节课推进多少）、当前进度（这门课讲到哪了）、题库状态（来自 `dsh-plugin-bankmanager`）。
- **输出**：明天会讲什么、今天该预习什么、今天该复习哪些知识点 / 哪几道题、哪些是历史遗留问题。

它不判题、不引导、不评价——只负责**排**。真正带着做的是 guide / HRL / work 三个模式。

## 安排法（草案）

**1. 明天会讲什么**
按课表找到这门课下一次上课的日子，内容 = 进度表里当前单元的**下一个单元**。进度由学生手动录（「今天讲到 2.3」），节奏写成「每次课推进 1 节」或「每天推进 N 页」；学生手动更新进度时以手动为准，推算不覆盖。

**2. 今天该预习什么**
下一次该科课要讲的内容，拆成两样：教材页码范围 + 三五个问题。问题不是提纲，是「你猜这一节为什么先引入这个概念」「如果先给你结论，你觉得它会怎么推出来」这种。

**3. 今天该复习什么**
从 `bankmanager` 取三类：`nextReviewAt <= 今天` 的到期题、最近错题、状态停在 `guide` / `hrl` 等处理的题。按学科分组、按当天可用时长限额（比如 25 分钟），先排快到期的，再排错得多的。

**4. 历史遗留问题**
超过 N 天没动、或同一道题错了两次以上的，单独列出来，问一句「今天要不要处理」。不硬塞进日常清单，但也不能一直藏着。

## 和别的插件怎么配合

- **只读 `bankmanager` 的库**：复习、待办、错题统计都从那里取。不替它改状态——状态由正在处理那道题的模式写回。
- **给 guide / HRL / work 派活**：清单里每一项都指向具体的题或知识点，点进去就是对应模式的会话。
- **不碰学科内容**：什么算「讲完了」由进度数据说了算，schedule 不自己判断教材内容。

## 还没定的问题

- **进度单位**：章节、页码还是知识点？直播班（成都七中网校）一般一天一节，是每天手录，还是能从教材目录推？
- **节奏**：按「每次课几节」还是「每周几节」；调课、假期、考试周怎么算例外。
- **输出形态**：每天早上推一条？晚上复盘推一条？还是界面上一个「今天」面板？
- **多科冲突**：同一天三门课都到期，谁优先——按到期时间还是按科目权重？
- **课表从哪来**：手录、导出文件，还是抄一份学校模板。
- **数据放哪**：`<dataRoot>/schedule/` 下的 JSON？和 bank 的库共用一份数据契约的话，契约以谁为准。
